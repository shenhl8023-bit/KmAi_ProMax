# 开目零件 XML 归类打分设计

日期：2026-08-21  
状态：已实现；打分卡 `v1-folder-calibrated` 已锁定  
范围：仅 PartClassification。不包含 KmAI 如何调用、如何展示。

## 目标

对外像一个模型：调用方只提供开目零件 XML，得到它落在**每一个已定义结构类**上的可能性、对应分数和原因。  
对内是确定性规则，不是黑盒。学（看 `.prt` 标定）和用（只读 XML 打分）分开。

## 非目标

- 不根据 XML 发明从未用 PRT 定义过的结构类
- 不在请求路径里打开 NX / 读取 `.prt`
- 不用件号定类
- 不上黑盒模型
- 不把分组模板 XML 和零件 XML 混为一谈
- 不在本文设计 KmAI 的工作流、Skill 或前端
- 打分卡锁定前，不把试算分当成类别结论

## 宏观形态

一个操作：`classify`。

```
调用方                 PartClassification
   │                          │
   │  零件 XML（路径或字节）    │
   │ ────────────────────────► │
   │                          │  GB2312 解码
   │                          │  抽指纹（内部）
   │                          │  套打分卡（内部）
   │                          │  判定 + 写理由
   │  各类：可能性、分数、原因  │
   │ ◄──────────────────────── │
```

调用方不需要知道指纹、权重、阈值。实现上先提供 Python 入口（函数或 CLI），协议就是下面这份 JSON；以后若套 HTTP，字段不变。

## 公开契约

### 输入

零件 XML，二选一：

- 文件路径
- 原始字节（按 GB2312 / GBK 解码；不要当 UTF-8）

不要件号、不要 PRT、不要模板类型。

### 成功（读得懂 XML）

主结果是 `types`：每个已用 PRT 定义过的结构类一条。未定不是其中一项，不去抢可能性。下面数字只是字段形状示意，不是标定结论。

```json
{
  "ok": true,
  "geometryClass": "sleeve",
  "labelZh": "活门衬套",
  "types": [
    {
      "id": "sleeve",
      "labelZh": "活门衬套",
      "possibility": 0.72,
      "score": 0.78,
      "reasons": [
        "最小内径/最大外径为 0.73，落在活门衬套期望区间",
        "内回转面占表面积为 0.38，符合空心薄壁"
      ]
    },
    {
      "id": "spool",
      "labelZh": "活门",
      "possibility": 0.28,
      "score": 0.31,
      "reasons": [
        "最小内径/最大外径为 0.73，偏离活门（细通孔）画像"
      ]
    }
  ]
}
```

字段约定：

| 字段 | 含义 |
|------|------|
| `ok` | 是否成功读入并解析为开目零件 XML |
| `types` | 主结果。每个已定义结构类一条，含可能性、分数、原因 |
| `types[].possibility` | 落在该类的可能性，`[0, 1]`，各类之和为 1（全部 `score` 为 0 时各类为 0） |
| `types[].score` | 该类与打分卡画像的匹配分，`[0, 1]`，各类不必相加为 1 |
| `types[].reasons` | 该类得这个分的原因，必须对应真实计算 |
| `geometryClass` | 便于调用方取的摘要：可能性最高的类；闸门触发时为 `unknown` |
| `labelZh` | 与 `geometryClass` 对应的中文 |

`score` 是打分卡算出来的匹配程度。  
`possibility` 由各类 `score` 按比例得到：`possibility_i = score_i / Σ score`（Σ 为 0 则各类可能性为 0）。这样「更像哪一类」可直接比，理由仍挂在可解释的 `score` 上。

`unknown` 是闸门，不进入 `types`，不占可能性。

### 打分卡未锁定

```json
{
  "ok": true,
  "geometryClass": "unknown",
  "labelZh": "未定",
  "types": []
}
```

此时内部可以抽指纹，对外不得填 `types`，不能把试算分当成各类可能性。

### 锁定后闸门触发（仍给各类可能性）

`geometryClass` 为 `unknown`，**但 `types` 仍返回每一类的可能性、分数和原因**，供调用方只展示、仍手选。触发条件见后文未定闸门。

### 失败（不是未定）

读失败不当成零件未定：

```json
{
  "ok": false,
  "error": "NOT_KMSOFT_XML",
  "message": "根节点不是 Kmsoft，或无法按 GB2312 解析"
}
```

典型原因：空内容、解码失败、不是 XML、没有 `<Kmsoft>` 根节点。

## 内部三层

公开契约稳定靠「调用方只认上述 JSON」。内部仍拆开，改一层不逼另外两层改公开字段。

```
开目零件 XML（GB2312）
        │
        ▼
  ① 指纹提取     同样 XML → 同样指纹
        │          缺字段或分母为 0 → 该因子 invalid
        ▼
  ② 打分卡套用   数据不是代码；未锁定则不下结论
        ▼
  ③ 判定 + 理由  与加分同一套规则；分不够或两家接近 → unknown
```

| 内部版本 | 锁什么 | 何时升 |
|----------|--------|--------|
| 公开 JSON 形状 | `ok` / `types`（possibility、score、reasons） / `geometryClass` | 增删公开字段 |
| 指纹算法 | 因子名、公式、invalid 规则 | 增删或改计算公式 |
| 打分卡 | 主次、权重、期望区间、未定阈值 | 标定更新或加新类 |

权重变化只换打分卡，不改公开字段名。

`classify` 只读卡。看 PRT、比 XML、填权重是线下标定，不在请求路径里。

## 指纹（内部，不对外）

用 `type` 与 `Param` 的 `name` 取值。件号不进指纹。  
**数值 0 是有效观测**（例如没有某类面就是 0）。**缺字段或分母为 0 才是 invalid**。

第一期不纳入打分：`Point_Set`、`Line_Set`、同轴孔系、内外回转面系组。标定后若要加入，升指纹算法版本。

只作分母或中间量、不直接当分数：总体积、表面积、内外回转面面积、最大外径、最小内径、薄壁圆柱厚度均值。

### 第一期因子

| 内部名 | 算法 | invalid |
|--------|------|---------|
| `hollow_ratio` | 最小内径 / 最大外径 | 缺任一端，或最大外径 = 0 |
| `inner_rev_ratio` | 零件总体内回转面表面积 / 零件总体表面积 | 缺任一端，或表面积 = 0 |
| `inner_cyl_balance` | 内圆柱总面积占比 / (内圆柱总面积占比 + 外圆柱总面积占比) | 缺占比，或两者之和 = 0 |
| `wall_to_outer` | 薄壁圆柱厚度均值 / 最大外径 | 缺任一端，或最大外径 = 0 |
| `slenderness` | 零件细长度 | 缺该字段 |
| `plane_ratio` | 平面总面积占比 | 缺该字段 |
| `inner_cyl_ratio` | 内圆柱总面积占比 | 缺该字段 |
| `outer_cyl_ratio` | 外圆柱总面积占比 | 缺该字段 |

XML 位置：

| 位置 | 用到的 name |
|------|-------------|
| `Part_Info` | 零件总体表面积、零件总体内回转面表面积 |
| `Part_OtherInfo` → 面分类信息 | 平面总面积占比、外圆柱总面积占比、内圆柱总面积占比 |
| `Part_OtherInfo` → 薄壁分类信息 | 薄壁圆柱厚度均值 |
| `Part_OtherInfo` → 主回转面信息 | 最大外径、最小内径 |
| `Part_OtherInfo` → 主惯性轴信息 | 零件细长度 |

invalid 因子本轮不参与加分，理由可写「未采用：…」。不得把 invalid 当成 0 分。

同一 XML 必须得到同一份指纹。下面这对样本只说明这些比值分得开，**不是权重，也不是正式结论**：

| 因子 | 计量活门衬套1 | 计量活门 |
|------|----------------|----------|
| `hollow_ratio` | 约 0.73 | 约 0.06 |
| `inner_rev_ratio` | 约 0.38 | 约 0.16 |
| `wall_to_outer` | 约 0.14 | 约 0.56 |

## 打分卡

打分卡是配置。每张卡有是否锁定。

每个已定义结构类（现在 `sleeve`、`spool`）对每个第一期因子有：角色（主/次）、权重、期望区间。区间用比值。  
数字见 `AGENTS.md` 打分卡一节与 `src/part_classification/data/scorecard.json`。`hollow_ratio`、`slenderness` 未进 v1 卡。

### 单类得分

锁定后，对每个结构类：

1. 只用「卡里有、且指纹有效」的因子。
2. 将因子值对期望区间映射为匹配度 `[0, 1]`：区间内为 1，越出为 0。
3. `score = Σ(权重 × 匹配度) / Σ(本轮实际用到的权重)`。
4. 全部类的 `score` 算完后：`possibility_i = score_i / Σ score`（Σ 为 0 则各类可能性为 0）。
5. 主因子若在卡中却 invalid → 本轮 `geometryClass` 为未定，不拿次因子硬撑；`types` 仍按上式给出。

理由与加分同源：每个类列出贡献最大的几条，写明实际值与期望区间。禁止空话。

### 未定闸门（打分卡已锁定时）

满足任一则 `geometryClass = unknown`，同时仍返回完整 `types`（各类可能性、分数、原因）：

- 有效因子少于 3
- 某个主因子 invalid
- 最高分低于 0.50
- 两类分差小于 0.10

读失败仍是 `ok: false`，不是未定。

### 加新类

1. 先有 `.prt` 样本，写清几何定义
2. 收录对应 XML，归到该类
3. 在打分卡中为该类增加画像
4. 新因子不得把已有类的区间改到互相覆盖
5. 升级打分卡标识；边界件记入 `AGENTS.md`

## 错误与可复现性

| 情况 | 对外 |
|------|------|
| 打分卡未锁定 | `ok: true`，未定，空 `types` |
| 锁定后画像不清或两家接近 | `ok: true`，未定，仍给完整 `types` |
| 无法解析为开目 XML | `ok: false` |
| 同一 XML + 同一张已锁定的卡 | 同一组可能性、分数和理由 |

实现之后至少覆盖：解码与根节点、invalid 跳过、未锁定不下结论、主因子缺失走未定、锁定后分数可复现、学习集 20 件与文件夹标签一致。`source/测试样本/` 不参与调卡。

## 与仓库流程的关系

学样本仍按 `AGENTS.md`：先看 `.prt`，看不准用文件夹预分类，冲突先问用户。  
打分卡是标定的产物，用来回答「几何上的衬套，在 XML 里哪些量高、哪些量低」，不能代替看三维。

现场 `classify` 只有 XML。没有几何真值，只根据已锁定的打分卡给出各类可能性、分数和原因。

## 关键决定

1. 对外只保留 `classify`：XML 进，每一类的可能性 / 分数 / 原因出。
2. 指纹、打分卡、阈值全部内部；调用方不依赖它们。
3. 未定是闸门，不进入 `types` 去抢可能性。
4. 卡未锁定：空 `types`。卡已锁定仍未定：照样返回各类可能性、分数和原因，便于只展示、仍手选。
5. `score` 是画像匹配分；`possibility` 是各类 `score` 的占比，之和为 1。
6. 优先比值，不用绝对尺寸当主依据。
7. 打分必须可解释，不加黑盒模型。
8. 没有 PRT 定义过的形状，不能单靠 XML 开新类。
9. KmAI 如何集成不在本设计内；JSON 契约保持稳定，由调用方自行封装。

## 实现顺序（已执行）

2. 第一期指纹提取与 invalid 规则
