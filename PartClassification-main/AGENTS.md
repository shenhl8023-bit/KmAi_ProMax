# AGENTS.md

本仓库只维护这一份全局说明。Grok、Codex、Claude 都读它。当前候选打分卡的重标定设计见 `docs/superpowers/specs/2026-08-24-xml-factor-recalibration-design.md`；操作规则仍以本文为准。

## 项目是干什么的

先从 NX 的 `.prt` **看懂零件几何上是什么类型**，再把对应的开目 XML **归到这一类**，并找出 XML 里哪些因子能代表这种几何。

分两段，不要混：

1. **学（必须有 `.prt`）**  
   看三维几何 → 认定类型（活门衬套、活门等）→ 把对应 XML 标成这一类 → 总结这类几何在 XML 里的画像。  
   类型以 `.prt` 结构为准；件号只是线索。看不准时，采用用户用文件夹做的人工预分类。
2. **用（现场往往只有 XML）**  
   用已经从 PRT 上学来的 XML 画像去猜类型。现场没有 PRT 是常态，不能要求每次都打开 NX。

没有几何标定过的类，不能凭空用 XML 发明。新类仍然要先有 PRT 样本。

## 目标

### 短期（当前阶段）

`classify` 已实现。默认打分卡为 **`v2-evidence-group-calibrated-candidate`**，`locked: true`、`validationStatus: candidate`，仅根据 20 对学习样本写入。

`locked: true` 表示经验范围、组权重与闸门已经固定，运行时可以输出分类；`validationStatus: candidate` 表示尚未完成两类独立外部验证。独立集目前只有两件用户确认的衬套、没有独立活门，不能宣称完整两类泛化准确率或“已验证生产卡”。

- 学习集：`source/活门prt/` 与 `source/活门衬套prt/` 各 10 件，及其 `source/XML样本/` 同名 XML
- `source/测试样本/`（`taotong`、`衬套`）**不纳入学习**，只做输入输出抽查
- 压差活门（`JRT145-17-01`）用户确认为活门，不改预分类
- 不要做训练、黑盒模型、HTTP 或 KmAI 集成

### 长期

- 每加一类：先用 `.prt` 把几何说清楚，再收录 XML，更新画像
- `classify`：读 XML → 内部指纹 → 按打分卡给出每一类的可能性、分数和原因（**输入只有 XML**）
- 样本增多后扩展结构类（轴、壳体、盘类等）
- 大类稳定后再考虑功能细类
- 现场：往往只有 XML，用 PRT 上学来的画像快速归类

## 分类原则

1. **标定类型看 `.prt`。** 学样本、加新类时必须先看三维，再给 XML 贴类。
2. **人工预分类在文件夹上。** `source/活门prt/` = 活门，`source/活门衬套prt/` = 活门衬套。这是用户给的预标注，可能有错。
3. **看不准就用文件夹类型。** 不要擅自改成「未定」或另一类。
4. **有疑问先问用户再改正。** 几何和文件夹明显冲突时，说明依据并请用户改预分类；未得到答复前仍沿用文件夹类型。
5. **现场归类看 XML。** 用已学画像猜测类型；此时没有 PRT 是正常的。
6. 件号只是线索，不能单独定类。
7. 不能对从未用 PRT 定义过的形状，单靠 XML 开一个新类。
8. 描述 XML 时优先用占比和比值，少用绝对尺寸。
9. XML 按 GB2312 / GBK 解码。不要当 UTF-8 读，也不要把乱码写回样本。
10. 现场 XML 画像不清则标「未定」。打分必须可解释。未要求前不要上黑盒模型。

## 第一期类别（结构类，由几何定义）

代码和指纹里用英文 id，对外用中文（与文件夹名一致）。**标定**时先看 `.prt` 外形，拿不准则用所在文件夹；**现场**时用 XML 画像去对齐这些类。

| id | 中文 | 预分类文件夹 | 几何上什么样（待用 PRT 逐件核对） |
|----|------|----------------|----------------------------------|
| `sleeve` | 活门衬套 | `source/活门衬套prt/` | 空心薄壁回转体，有明显内孔/内腔，壁相对薄 |
| `spool` | 活门 | `source/活门prt/` | 细长台阶回转体，外圆带多道肩/槽，内部多为细通孔 |
| `unknown` | 未定 | 无对应文件夹 | 仅用于现场 XML 画像不清，或用户确认后的待定件 |

后续类别同样必须先有 `.prt` 样本、先写清几何定义，再收 XML。

## 样本与模板映射

`source/模板/` 存放开目分组模板（如 `套筒类模板.xml`），`source/模板/模板映射.json` 记录「哪个样本用哪个模板」。界面：`py -3 -m part_classification.gui` 或 `part-classify-gui`。

边界：

1. 只登记映射，不解析模板内容、不校验模板结构、不生成或回写 XML。模板是否规范由开目负责。
2. 映射键是单个样本文件名，不做件号前缀或几何类的继承。
3. 模板库就是 `source/模板/*.xml` 的目录扫描结果；新增模板只需放入文件，重新扫描即可见。
4. 映射不参与打分卡判定，不影响 `classify` 的 `geometryClass` 与 `similarParts`；它只是登记信息，不是几何真值。
5. 映射指向的模板或样本被删除后，映射保留并标记缺失，由用户决定修改或删除。

## 从几何到 XML 的工作顺序

对每一个零件：

1. 记下该 `.prt` 所在文件夹给出的预分类（活门 / 活门衬套）。
2. 打开或还原三维外形，按几何定义核对。
3. 看准且与文件夹一致：采用该类型。看不准：采用文件夹类型。与文件夹冲突：向用户说明几何依据，请用户改正；未答复前仍用文件夹类型。
4. 打开对应 XML，归到第 3 步认定的类。
5. 全部标定后再在已标定 XML 上比较因子（主次已写入；测试样本不参与这一步）。

因子排序和打分卡是第 4 步的产物，用来回答：「几何上的衬套，在 XML 里通常哪些量高、哪些量低？」不是用来代替第 1、2 步。

## XML 读哪些

根节点 `<Kmsoft>`。用 `type` 和 `Param` 的 `name`。

| 位置 | 用途 |
|------|------|
| `Part_Info` | 体积、表面积、内外回转面面积，作分母 |
| `Part_OtherInfo` → 面分类信息 | 平面 / 外圆柱 / 内圆柱等占比 |
| `Part_OtherInfo` → 薄壁分类信息 | 薄壁圆柱厚度均值 |
| `Part_OtherInfo` → 主回转面信息 | 内外表面占比、最大外径、最小内径 |
| `Part_OtherInfo` → 主惯性轴信息 | 第一期用细长度；扁平度、包围盒先不进打分 |
| `Point_Set` / `Line_Set` | 与 PRT 外形对照；第一期不进打分 |

派生量（内部指纹，不对外）。**0 是有效观测；缺字段或分母为 0 才 invalid。**

```
hollow_ratio      = 最小内径 / 最大外径
inner_rev_ratio   = 零件总体内回转面表面积 / 零件总体表面积
inner_cyl_balance = 内圆柱总面积占比 / (内圆柱总面积占比 + 外圆柱总面积占比)
wall_to_outer     = 薄壁圆柱厚度均值 / 最大外径
slenderness       = 零件细长度
plane_ratio       = 平面总面积占比
inner_cyl_ratio   = 内圆柱总面积占比
outer_cyl_ratio   = 外圆柱总面积占比
```

最大外径为 0 时不算 `hollow_ratio`、`wall_to_outer`。表面积为 0 时不算 `inner_rev_ratio`。内外圆柱面积占比之和为 0 时不算 `inner_cyl_balance`。invalid 因子跳过，不当 0 分。

## 因子排序（v2 重标定，20 对学习样本）

只在已标定的 20 对 XML 上比较。`source/测试样本/` 不参与排序。

排序强度为 `evidence_strength = directional_auc × family_leave_group_out_accuracy × bootstrap_auc_lower_95`，排序如下：

```text
inner_cyl_balance > inner_cyl_ratio > outer_cyl_ratio > inner_rev_ratio
> wall_to_outer > hollow_ratio > plane_ratio > slenderness
```

三项圆柱面因子高度相关，只作为一个圆柱面构成证据组，由 `inner_cyl_balance` 代表；`inner_cyl_ratio`、`outer_cyl_ratio` 只保留诊断，不重复加分。`hollow_ratio`、`slenderness` 不进入候选生产分数。不要只用件号、也不要在未看 PRT 的情况下用 XML 分数代替第 1 步。文件夹预分类可以当默认标签，但几何冲突必须问用户。

## 打分卡（v2-evidence-group-calibrated-candidate，已锁定候选卡）

生产卡：`src/part_classification/data/scorecard.json`，`locked: true`、`validationStatus: candidate`。`classify` 只读卡，不在请求里看 PRT。

匹配度：区间内为 1，越出为 0。四个生产证据组的权重依次为 `0.406191 / 0.223875 / 0.222678 / 0.147255`；六位小数相加为 `0.999999`。评分按本轮实际有效组的权重和归一化，这些值不是训练结果、概率或总体最优值。

生产 JSON 使用学习 XML 的全精度经验最小值/最大值。下表约保留 9 位小数，仅为展示；实现不得用展示值替换全精度端点，以免严格边界排除真实极值。

| 证据组 / 代表因子 | 角色 | 权重 | 活门衬套区间 | 活门区间 |
|------|------|------:|--------------|----------|
| 圆柱面构成 / `inner_cyl_balance` | 主 | 0.406191 | [0.433380084, 0.502170767] | [0.071212121, 0.418158568] |
| 内部回转面 / `inner_rev_ratio` | 辅助 | 0.223875 | [0.371801970, 0.603647895] | [0.060164917, 0.438915538] |
| 薄壁 / `wall_to_outer` | 辅助 | 0.222678 | [0.139818182, 0.358200000] | [0.216444444, 0.564250000] |
| 平面 / `plane_ratio` | 辅助 | 0.147255 | [0.074000000, 0.258000000] | [0.195000000, 0.373000000] |

闸门：主因子必须有效且唯一命中一个类别；至少一个独立辅助组支持主方向；辅助总分不能推翻主方向；最高分并列返回未定。候选卡不再沿用固定 `0.50` 最高分与 `0.10` 分差闸门。

验证边界：20 件学习样本回放 20/20 是配置一致性，不是泛化准确率；两件独立衬套通过；按系列留组为 16/20 正确、4/20 未定、0 误判。`JRT145-17-01压差活门` 保持活门。

未锁定路径仍保留：显式传入 `locked: false` 的卡时，`types` 为空。读失败是 `NOT_KMSOFT_XML`，不是未定。

入口：`from part_classification import classify`，或 `py -3 -m part_classification <xml路径>`。输入是路径或原始字节。

当前候选打分卡细则见 `docs/superpowers/specs/2026-08-24-xml-factor-recalibration-design.md`。`2026-08-21-xml-classify-scoring-design.md` 仅为 v1 初版历史设计，不作为当前卡入口。

## 指纹与对外输出

指纹只在内部。对外成功形态是 `classify` 的 JSON：`ok`、`types[]`（`id` / `possibility` / `score` / `reasons`）、以及摘要字段 `geometryClass` / `labelZh`。UTF-8。

学样本时有 PRT：几何真值记在标定记录里，不靠现场接口回传。  
现场只有 XML：没有几何真值，只根据届时锁定的打分卡给出各类可能性、分数和原因。

实现阶段如需把指纹落盘，再用 UTF-8 写到 `output/fingerprints/`；那不是给调用方的契约。

## 以后加新类时

1. 先放入对应预分类文件夹（或新建文件夹），从几何上写出这类长什么样
2. 再放入对应 XML，归到该类
3. 重算 XML 因子分离度
4. 新因子不得明显破坏已有几何类的 XML 画像
5. 升级打分卡标识，边界件记在本文档

## 智能体现在怎么做

- `classify` 已实现，默认卡为已锁定的候选卡 `v2-evidence-group-calibrated-candidate`。改权重只改打分卡并升级 `id`；没有独立活门验收样本前，`validationStatus` 保持 `candidate`。
- 用户给的是 `.prt`（或 PRT+XML）：先看几何；拿不准用所在文件夹预分类；和文件夹冲突则问用户，不要擅自改。
- 用户只给 XML：按锁定打分卡给出各类可能性、分数和原因；这不是几何真值。
- `source/测试样本/` 只做输入输出抽查，不要拿它们调区间或权重。
- 读 XML 用 Python 按 GB2312 解码（`classify` 已按此处理）。直接当 UTF-8 读会把中文 `name` 读乱。
- 说明结论时：采用的类型、是几何看准的还是沿用文件夹的；若有疑问，明确提出来请用户改。
- `_preview_out/` 只是外形核对草稿。
