# XML 查询相似零件与三维展示设计

日期：2026-09-29
状态：设计已获用户确认，待拆分实施计划
范围：KMAI 普通 HTTP 接口与前端、PartClassification/step-compare 的库级复用；不修改 MCP 函数实现

## 1. 目标与边界

用户在 KMAI 第一步选择一个零件 XML，点击“查询相似零件”，系统从 XML 样本库计算最相似的三个零件，并在同一界面展示当前零件与候选零件的三维模型。用户可以切换三个候选，点击“应用当前分组模板”后，系统把当前候选绑定的模板接入原有 KMAI 分组模板应用流程。

资源以去掉扩展名后的文件名作为零件标识：XML 库、STEP 库和模板映射分别配置目录/清单。数据库完整性是前置约束：每个零件都应有 XML、STEP/STP 和分组模板；发现缺失时返回明确错误，不用较低排名的零件替换。

明确不在本功能内修改：MCP 函数定义、工具注册表、工具分发器、命名管道客户端、3DMPS 调用实现及现有 `apply_group_template` 实现。KMAI 只增加普通 HTTP 路由、编排服务、前端和配置。

## 2. 用户流程与界面

1. 第一步卡片标题从“选择分组模板”改为“查询相似零件”。
2. 用户选择 `.XML` 文件；前端调用上传接口，上传成功后启用查询按钮。
3. 点击查询后，后端运行现有 XML 分类/相似度算法，返回 Top 3 候选及每个候选的 STEP、模板和相似度元数据。
4. 页面显示左右两个三维视口：左侧固定当前零件，右侧显示当前候选。候选卡片或上一个/下一个按钮切换 Top 1、Top 2、Top 3；不做按时间自动轮播。
5. 用户点击“应用当前分组模板”时，操作对象是右侧当前候选。成功后复用现有 KMAI 第一步完成状态并进入第二步。

三维视图只加载服务端生成的 GLB URL，不向浏览器返回本机绝对路径。候选卡显示零件名、排名、相似度和模板名；资源缺失时显示明确错误并禁止应用。

## 3. 后端接口与数据流

新增普通 HTTP 接口（不进入 MCP 工具注册）：

### `POST /api/similar-parts/upload`

请求携带 XML 文件名和内容（实现可采用当前本地服务可控的 JSON/Base64 形式，限制总大小）。服务端按 GB2312/GBK 解析并验证 Kmsoft XML，将内容放入带 TTL 和大小上限的本地内存缓存，返回不透明 `uploadId`、文件名和状态。错误包括文件过大、不是有效 Kmsoft XML、上传缓存已满。

### `POST /api/similar-parts/query`

请求：`{ "uploadId": "...", "topK": 3 }`，`topK` 固定为3或限制在1到3。服务端从上传缓存读取 XML，调用 `part_classification.classify`/现有相似度实现，按样本名解析对应 STEP 路径和模板映射。返回当前零件信息、最多三个按相似度降序排列的候选、相似度、分类标签、模板标识和模型标识。候选资源缺失时返回数据库配置错误，不静默跳过。

### `GET /api/similar-parts/models/{modelId}.glb`

服务端仅允许访问已由查询结果登记的模型 ID，读取配置 STEP 目录中的同名 `.stp`/`.step`，复用 `step-compare` 的 STEP→GLB 转换和缓存策略。模型缓存为本机短生命周期缓存，服务退出即失效。

### `POST /api/similar-parts/apply-template`

请求：`{ "uploadId": "...", "candidateId": "..." }`。服务端根据服务端保存的查询结果重新解析候选，读取候选绑定的模板 XML，校验文件名与目录边界，将模板写入现有 3DMPS 分组模板保存目录，然后调用现有普通工具接口 `AGENT.tool("apply_group_template", ...)`。前端传入的路径、模板名不能直接作为文件系统路径使用。成功响应包含模板名和现有工具结果；失败响应不泄露 traceback、绝对路径或内部配置。

查询结果和上传内容均按 TTL 清理，候选 ID 与模型 ID 使用不透明值或受控哈希，不能让客户端构造任意本机路径。

## 4. 配置与模块边界

在 KMAI 本地 `config.ini` 增加 `[SimilarParts]` 配置，至少包括：

- `xml_library_dir`：XML 样本库；
- `step_library_dir`：STEP/STP 模型库；
- `current_step_file`：可选的当前模型 STEP；用于 `AIBasicInfo.xml + stepModel.stp` 这类固定导出文件名，留空时仍按 XML 同名查找；
- `template_map_file`：XML 样本名到模板名的映射清单；
- 上传大小、缓存 TTL、模型缓存上限。

新增独立的普通后端编排模块负责上传缓存、库路径解析、查询结果登记、模型转换调用和模板应用；不把相似度算法复制到 KMAI。`PartClassification` 继续作为 XML 指纹/相似度库使用，`step-compare` 继续作为 STEP 网格化库使用。前端保持原生 ES Module，不引入新的构建系统；Three.js 和已有对齐/分屏逻辑优先复用。

## 5. 错误、安全与兼容性

- 仅接受 `.xml`/`.XML`，内容必须通过 Kmsoft XML 校验；按 GB2312/GBK 解码。
- 仅监听现有本机 HTTP 服务；上传、查询、模型和应用接口都服务于本地会话。
- 所有路径由服务端配置解析，并做 `basename`/`commonpath` 边界校验；不返回绝对路径。
- 缺少同名 STEP、模板映射或模板文件时返回稳定错误码和零件名；不改变排名。
- 保留原有工作流和原有普通 `/api/tool` 行为；未使用新界面时不影响旧流程。
- 应用模板失败时不标记第一步完成，允许用户重新选择候选或重试。

## 6. 验证与验收

后端测试覆盖：XML 上传成功、GB2312 解码、非法 XML、大小限制、TTL 清理、查询 Top 3 排序、同名 STEP/模板解析、缺失资源错误、模型 ID 越权、候选 ID 越权、模板路径穿越防护，以及应用模板成功/失败时的工作流状态。

前端测试覆盖：上传前查询按钮禁用、上传后启用、查询加载/错误态、左右模型加载、Top 3 手动切换、当前候选模板显示、应用成功后进入第二步、应用失败可重试和旧工作流卡片不受影响。

Windows 实机验收必须连接真实 KMAI 服务、3DMPS 命名管道和 STEP 转换依赖，验证：上传 XML → 查询 → 三维左右展示 → 切换三个候选 → 应用模板 → 进入原有第二步。macOS/Linux 仅做不触发 Windows 管道的静态检查和单元测试。

## 7. 明确假设

- 候选 XML、STEP/STP、模板映射采用去扩展名后的同名零件标识；当前模型默认同名，也可通过 `current_step_file` 指向固定导出的 STEP。
- 数据库正常情况下每个样本的三类资源都存在；缺失属于配置/数据错误。
- “轮询前3个”解释为用户手动切换候选，不做自动定时轮播。
- 当前查询输入主要是 XML 文件；当前零件的 STEP 由输入 XML 文件名在 STEP 库中查找，不要求用户再次上传 STEP。
